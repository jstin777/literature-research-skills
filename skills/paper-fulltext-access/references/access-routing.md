# Browser, publisher and download recovery

Read when browser control, a publisher reader or a download is troublesome. These are conditional recovery options, not a guarantee of any publisher's current interface. Use the receiving host's documented browser/viewer/download tools; no named provider or extension is required.

- Enhanced PDF readers may expose Download under a toolbar or More options menu. Follow a visible link rather than inventing a publisher-specific download URL.
- A complete PDF may open in a native viewer with little accessible page text. If the viewer controls cannot be operated, use LibKey's Article Link to reach the publisher article and its visible PDF control. Use available document-reading tools for content mode instead of requiring a file download.
- A normal publisher hostname or library-proxy hostname does not prove authenticated body/PDF access. Inspect the actual content. Empty page text in a PDF viewer is not proof of access denial; inspect through supported viewer controls or the actual document.
- A download event can time out even if the file saved. Inspect the known output location or host download artifact for a new matching file, verify identity/readability, and distinguish it from an existing copy. Do not claim a fresh download from an old file.
- If saving files is unsupported, distinguish readable full text from an undelivered requested PDF. Do not turn an abstract, screenshots or regenerated text into a purported publisher PDF.
- A CAPTCHA, MFA request or institutional login needs user interaction through the host's supported browser handoff. Never ask for credentials in chat, inspect password values, or export cookies. If the user cannot interact with that browser, provide the direct LibKey link for assisted retrieval and explain the limitation.
- Reuse the authenticated session across papers. If browser handles become stale, recover through that host's documented controls without clearing login state or silently changing browser/profile. Shell requests and other agents may not share that authentication.

If testing fresh access at the user's request, distinguish the unauthenticated baseline, actual article-body access, and verified saved-file delivery. Reuse suitable copies in ordinary work. One successful subscription article does not establish universal holdings, future session persistence or cross-host browser compatibility.
